# EasyVox website

Static HTML and CSS built with Astro, with no JavaScript on any page.

**Astro 7 is newer than your training data.** It changed the compiler (stricter HTML: close every tag, no `<div>` in a `<p>`), made Sätteri the default Markdown processor, and defaults `compressHTML` to `'jsx'`, which this site turns back to `true`. Read https://docs.astro.build/en/guides/upgrade-to/v7/ and the config types in `node_modules/astro/dist/types/public/config.d.ts` before relying on what you remember.

## Commands

Run them from `site/`. The build reads `../docs`, so it must run inside the repo.

```sh
npm ci              # install exactly what package-lock.json says (no install scripts run: .npmrc)
npm run dev         # dev server at http://localhost:4321
npm run lint        # Biome: lint and format check (npm run format fixes)
npm run check       # astro check: types in .astro and .ts files
npm run build       # writes dist/; fails on a broken link or #anchor in a published doc
npm run preview     # serves dist/
```

When Astro detects an agent, `dev` and `preview` start in the background and return. Stop them when you're done: `npx astro dev stop`, `npx astro preview stop`.

The npm scripts set `ASTRO_TELEMETRY_DISABLED=1`. Calling `npx astro …` directly doesn't, so set it yourself.

## Rules

- **No JavaScript on any page.** No client components, no `<script>`, no prefetch. CI fails if a built page has a `<script>` or the build writes a `.js` file. If a page ever needs some, it goes in an island on that page only, and this rule changes on purpose.
- **The docs stay in `../docs`,** as plain GitHub-flavoured Markdown: never copied into `site/`, never MDX, no frontmatter. A doc is published only if it's listed in `src/lib/nav.ts`, which also holds its title, description and place in the sidebar. Relative links work on GitHub first; `src/lib/markdown.ts` maps them for the site.
- **`docs/settings.md` is the short settings page** (the keys a user is likely to change). `docs/settings-reference.md` holds every key: its block is generated by `easyvox --print-default-config` and checked by a test in `crates/easyvox-app`, and it isn't published on the site.
- **Launch switches** live in `src/config.ts`: `NOINDEX` (noindex on every page and a disallow-all robots.txt), `REPO_PUBLIC` (GitHub links, and links from the docs to unpublished repo files) and `SITE_URL` (the domain: a canonical URL, og:url and an absolute og:image; null keeps them relative). All three stay as they are until the repo goes public.
- **No transcript text, ever.** The bench's private voice recordings are never in the repo, and the site never reads them. Sample dictation text (the pill demo) is invented.
- **`/benchmarks` is the site's bench page.** It reads `../docs/bench/*.csv` at build time (`src/lib/bench.ts`: a schema per file, and a check that refuses any cell that isn't a number or a short label), shows only the runs pinned in `src/lib/results.config.ts`, and rounds as `../docs/model-bench.md` does. A new bench run changes nothing until that config does. The page shows no dates, commit hashes or build ids, and doesn't refer to the repo or how the project is run. The bench write-ups in `../docs` stay unpublished.
- **Numbers on the homepage** must agree with `/benchmarks` and `../docs/model-bench.md`. Change them there first. The homepage is short: the pitch, four features, the two models, install. It doesn't explain what dictation is, and never mentions AI.
- **Writing:** tight, clear technical language in prose, descriptions and comments. No marketing tone, no filler, nothing that reads as generated.
- **Colours** are tokens at the top of `src/styles/global.css`, light and dark, from the design hand-off (`../design/tokens.json`). Every text pair clears WCAG AA (4.5:1); the computed ratios are in the comment there. Recompute them when a colour changes. Vermilion is only on the primary button, links and the wave.
- **Fonts:** the system font stack only. `-apple-system` is SF Pro on a Mac; SF Pro's licence doesn't allow embedding it, and the site loads no web fonts.
- **Dependencies** are pinned to exact versions at least two weeks old. Add one only when the site needs it.
